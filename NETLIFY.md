# Deploying nxt.bargains on Netlify

This is a Next.js 15 (App Router) app. `netlify.toml` + `@netlify/plugin-nextjs`
handle SSR / ISR / API routes automatically. Two things are specific to this app
and must be set up before it works fully on Netlify.

## 1. Environment variables (Netlify → Site settings → Environment variables)

Set these (the values live in `.env.local` locally, which is git-ignored):

**Required**
- `NEXT_PUBLIC_STRAPI_URL` = `https://cms.fxnstudio.com`  (the PUBLIC Strapi URL)
- `STRAPI_API_TOKEN` = read token
- `NEXT_PUBLIC_SITE_URL` = `https://nxt.bargains`
- `NEXT_PUBLIC_AMAZON_AFFILIATE_TAG`

**Do NOT set** `STRAPI_INTERNAL_URL` on Netlify — it points at `127.0.0.1:8888`
(the local box) and won't resolve. Leaving it unset makes the app use the public
`NEXT_PUBLIC_STRAPI_URL`.

**Coupons / affiliates** (as used)
- `COUPON_FEED_SOURCE` = `couponapi`
- `COUPONS_API_PAUSED` = `true`
- `COUPONAPI_KEY`, `RAPIDAPI_KEY`
- `TAKEADS_PUBLIC_KEY`, `TAKEADS_SUB_ID`
- `IMPACT_ACCOUNT_SID`, `IMPACT_AUTH_TOKEN`, `IMPACT_WALMART_CATALOG_ID`, `IMPACT_TRACKING_TEMPLATE`
- `EBAY_CLIENT_ID`, `EBAY_CLIENT_SECRET`, `EBAY_EPN_CAMPAIGN_ID`
- `AWIN_*`, `TRADEDOUBLER_*`, `FEEDICO_API_TOKEN` (optional / inactive)

## 2. Runtime data files (`data/*.json`)

Several pages read local JSON at runtime (coupons, the 18k-store directory,
best-sellers): `coupon-stores.json`, `coupon-store-coupons.json`,
`coupons-couponapi.json`, `high-intent-coupon-stores.json`, `best-sellers*.json`,
`impact-links.json`, etc.

These are **git-ignored** (`/data/*.json`) and regenerated by the `scripts/` cron
on the native server. On Netlify the function filesystem is **read-only and
ephemeral**, and the cron can't run — so those files must be provided another way.

Choose one:

- **A. Commit a curated data snapshot (simplest).** Un-ignore the needed files so
  they ship with the build; `netlify.toml` already bundles `data/**` into the
  functions. Coupons/stores are then a snapshot, refreshed by re-deploying
  (trigger a Netlify build from a scheduled function or after the cron updates
  the data on the source box + pushes). —
  too large; the app degrades gracefully without it (links wrap live / fall back).
- **B. Fetch at build time.** Add a `prebuild` step that pulls the data into
  `data/` before `next build` (e.g. run the `scripts/fetch-*` against the APIs).
  Keeps data fresh on each deploy without committing caches.
- **C. Move data to a store.** Read coupons/stores from Strapi (`nxt-coupons`,
  already scaffolded) or Netlify Blobs instead of the filesystem — the most
  "serverless-native" option, but a larger refactor.

Recommended: **A** to get live quickly, then migrate coupons to **C** (Strapi)
over time.

## 3. Caveats already handled in code
- Runtime cache writes are wrapped in try/catch so Netlify's
  read-only FS doesn't crash renders.
- `included_files = ["data/**"]` in `netlify.toml` bundles committed data into
  the SSR/functions.

## 4. Not on Netlify
- The `scripts/*.mjs` cron jobs (coupon/deal/best-seller refresh) run on the
  source server, not Netlify. To refresh data on Netlify, use option B, a Netlify
  Scheduled Function, or trigger a build hook after the source cron updates data.
